A native macOS terminal for running many Claude Code and Codex sessions side by side.

Sessions are grouped into projects in a sidebar, each one keeps its conversation across relaunches, and each can run in its own Git worktree. See which session is working, which one is done and which one needs you, and answer Allow or Deny without switching to it.

What it does

Projects and sessions

A project is a folder plus a default command; its sessions live under it in the sidebar. Drag to reorder or move sessions between projects, rename them, give them colors. ⌘T for a new session, ⌘K to jump to one.

Conversations that resume

Claude sessions keep their pinned conversation UUID; Codex sessions keep the thread ID Codex assigns. Quit omux, reopen it, and Restart or Continue picks up that exact conversation.

Live status, Dock badge, notifications

Each session shows whether its agent is working, needs you, or is done. The Dock badge counts sessions waiting on you. When a session you aren't looking at needs you, a macOS notification opens it on click.

Allow or deny from the sidebar

Claude tool permissions and Codex command and file-change approvals show up as Allow and Deny buttons in the sidebar and the session header, so a session that stopped to ask doesn't need a tab switch.

Subagents

While Claude Code or Codex runs subagents, the selected session lists them in the sidebar with what each one is doing. Click one in the header's agents button to read its transcript in the right panel.

Worktree sessions with pull request status

⌥⌘T gives a session its own branch and folder next to the repo, so parallel sessions don't touch each other's files. A setup command can prepare each worktree first. With gh installed, the session shows its pull request's checks, reviews and merge state, and offers to clean up once it's merged.

Files, Changes and Browser

Files previews what the session is working on, with ⌘-click on paths in the terminal. Changes shows the diff against the base branch; click a line to leave a note and send them all to the agent in one message. Browser opens the local server the session prints and can pick an element into the prompt.

Usage limits

The sidebar shows the selected provider's plan limits, read from the same endpoint Claude Code's /usage uses, or from Codex's rate limit API. It says what's wrong when it can't.

Codex sessions

A project or session can run Codex instead of Claude Code. Pick the agent in the project or session settings, in the worktree sheet, or with File › New Codex Session. omux starts a private Codex app-server per session and uses Codex's existing CLI login; it doesn't implement its own login or read Codex's credentials.

Needs Codex CLI 0.165 or later installed as codex. The app-server integration is experimental on the Codex side.

  • Live status in the sidebar and header
  • Allow and Deny for command and file-change approvals
  • Subagents and their transcripts
  • Conversations that resume after a relaunch
  • Recent Codex conversations (⇧⌘O)
  • Codex usage limits

Install

Requirements

  • macOS 14 or later
  • Claude Code installed as claude for Claude sessions; plain shell sessions work without it
  • Codex CLI 0.165 or later installed as codex, optional, for Codex sessions
  • GitHub CLI, optional, for pull request status

Download

Get the disk image from the latest GitHub release, open it and drag omux to Applications.

omux-0.6.0.dmg

The app is signed with a Developer ID and notarized by Apple, so it opens like any other download. A zip of the same build is attached to each release for scripts.

Or build from source

Building from source needs Swift 6.2 or later, with a matching Xcode or Command Line Tools toolchain. Downloading the app does not require Swift. build.sh builds a release binary for your Mac and replaces /Applications/omux.app, signed with your Apple Development certificate if you have one, ad hoc otherwise.

git clone https://github.com/onurozcan/omux.git
cd omux
./build.sh
open /Applications/omux.app

Privacy

omux has no telemetry. It makes three kinds of network requests, all for features you can see:

  • Usage limits. To show your plan limits, omux reads Claude Code's login from the macOS Keychain and sends it to the Claude usage endpoint, the same one Claude Code's /usage command uses. The token is never written to disk or logged.
  • Pull request status. If gh is installed, omux runs gh pr view for each worktree session's branch. gh uses its own login; omux never reads your GitHub token.
  • Updates. About once a day, omux fetches omux.app/appcast.xml to see whether a newer version exists, and downloads it from GitHub only when you accept. Nothing about you or your machine is sent.
  • Codex. omux talks to its own Codex app-servers over authenticated loopback WebSockets, with analytics disabled. Codex itself connects to whatever your Codex settings say.

The Privacy section of the README lists every local file omux reads or writes.
