# Features

Everything omux does, in detail. The [README](../README.md) has the short version.

- **Projects and sessions.** A project is a folder plus a default command; sessions live under it in the sidebar. Drag to reorder or move sessions between projects, rename them, and give them colors.
- **Agent selection.** Choose Claude Code, Codex, a plain shell, or a custom command in project/session settings. File › New Codex Session starts Codex directly. Worktree sessions also have an agent selector.
- **Conversations that resume.** Claude sessions keep their pinned UUID; Codex sessions keep the thread ID assigned by Codex. Restart and Continue reopen that exact conversation.
- **Live status.** Each session shows whether its agent is working, needs you or is done, and the Dock badge counts sessions waiting on you.
- **Notifications.** When a session you aren't looking at needs you, omux posts a macOS notification with a sound; clicking it opens the session. Notifications for finished sessions are optional, and Settings can make it sound only, with the macOS sound of your choice. Programs can send their own with OSC 9 or OSC 777: set Claude Code's notification channel to `ghostty` (in `/config`) to get its notifications, and its plugins', this way. Turn each kind on or off in Settings › Notifications.
- **Allow or deny from the sidebar.** Claude tool permissions and Codex command/file-change approvals can be answered in the sidebar or header. Codex's info button shows the requested command or reason. Other Codex permission forms and questions are answered in its terminal.
- **Subagents.** While Claude Code or Codex runs subagents, the selected session lists them in the sidebar with what each one is doing; other sessions show a count. The header's agents button lists them all, and clicking one opens its transcript in the right panel.
- **Worktree sessions** (⌥⌘T). A session can get its own Git branch and folder (`<repo>.worktrees/<branch>` next to the repo), so parallel sessions don't touch each other's files. Turn it on per project to make it the default. A project can also have a setup command that runs in each new worktree before the session starts, such as `cp "$OMUX_REPO/.env" . && npm install` (`$OMUX_REPO` is the main checkout), so files Git ignores and dependencies are there before the agent begins. Right-click a worktree session to create a pull request, merge it into its base branch or open its folder; closing one asks whether to keep or delete the worktree.
- **Pull request status.** With the [GitHub CLI](https://cli.github.com) installed, a worktree session whose branch has a pull request shows its number and state in the sidebar and header: checks running or failing, changes requested, approved or merged. Click the header chip to see each check and open it on GitHub. When checks fail, "Send Failing Checks to Session" (in the chip and the session menu) fetches the failed steps' logs of each GitHub Actions check and pastes them into the session for you to review and send. The session asks for your attention when checks start failing, a review comes in or the pull request is merged. Once it's merged, the session offers to delete its worktree and branch.
- **Right panel** (⌥⌘F), with three tabs:
  - **Files** (⌥⌘1). Text files under 1 MB open in a small editor with syntax colors and line numbers; ⌘S saves in place, Tab indents the way the file does, and a file the agent changes while you look updates live. With unsaved edits, a change on disk shows Reload and Save mine instead. Markdown shows rendered until the pencil switches it to the editor. Browses the session's folder and previews Markdown, code and text (with optional line wrapping), images, PDFs, audio, video, and anything else Quick Look can show. File paths mentioned in the session's output are listed at the top; ⌘-click a path in the terminal to preview it.
  - **Changes** (⌥⌘2). The session's diff: against the base branch for worktree sessions, uncommitted changes otherwise. Click a line to leave a note, then send all notes to Claude in one message. It keeps itself up to date, and the sidebar shows each worktree session's added and removed lines.
- **Transcript view** (beta). Settings › Session View shows every session in the main panel as chat instead of the terminal, which keeps running underneath at full size; in a shell session the first message starts the agent chosen in Settings: prompts on the right, replies as markdown, tool calls grouped with their first result line and expandable output, Edit rows linking to Changes, and the permission card with Allow and Deny when the agent is waiting. Claude Code sessions are read from the transcript file in `~/.claude/projects`; Codex sessions from the thread over `codex app-server`. Edits expand into a diff, commands into their output, and long runs of tool calls fold. The conversation is drawn by WebKit from files inside the app (marked for markdown, highlight.js for code); nothing loads from the network, and links open in your browser. The box at the bottom types into the terminal, so slash commands and multi-line prompts work as they do there; sending into a session that isn't running starts its agent first, and Claude Code's folder trust question gets a Trust button. Each reply carries its model and token counts, thinking folds under it, todo lists render as checklists, subagent rows show live progress and open their transcripts, failed tool calls open by default, file paths open the Files preview, ⌘F searches the conversation and a pill jumps to the latest message. When Claude Code waits, the card above the box shows what it asks: the pending edit as a diff with Allow, Allow for session and Deny; a plan with its approval options; a multiple-choice question with its options. The box offers an agent-and-model menu (Claude Code's models under the Claude mark, Codex's under the OpenAI mark, read live from the app-server; a model of the other agent switches the session to it, resuming that agent's earlier conversation in the session when there is one, with a hand-off of what happened meanwhile), / commands (built-ins, your commands and skills), @ file mentions over the project, pasted images, ↑ for earlier prompts, a draft per session, and the permission mode as a chip you can click to cycle. `/mcp`, `/plugins`, `/skills`, `/agents`, `/hooks`, `/permissions` and `/commands` show an overview read from Claude Code's files right in the conversation. `/mcp` also checks each server the way a new session would and shows whether it is connected, needs sign-in, or failed and why; Sign in and Reconnect drive the session's own /mcp dialog so the running session gets the connection. MCP servers can be added, removed and signed in to, plugins enabled, disabled and uninstalled, and permission rules added and removed from there; omux runs `claude mcp` and `claude plugin` for the first two and edits the settings files for the third, and changes apply to sessions started afterwards. A button opens the terminal dialog for the rest. Other slash commands that open a dialog on the terminal, such as `/config` or `/model`, bring the terminal forward until the conversation moves on or you click Back to transcript; a Terminal button in the metrics line does the same on demand. The reply streams in from the terminal screen while the agent writes, edits show the line they landed on, images tools return show inline, long outputs fold to head and tail, and a summary strip at the top gives the start time, turns, files changed, tokens and branch. `/status` shows the Claude Code version and account. Slash commands you run read as what they did, such as "Effort changed to max". While the agent works, a stop button interrupts it (⌘.); a mic button dictates; drafts survive a relaunch; a message sent mid-turn is queued by the agent and shows in an "Up next" strip along the bottom of the chat, read from Claude Code's own queue records, where it can be moved earlier or later or pulled back; attached files show as chips above the field and can be dropped onto the box. ⌥⌘P shows the terminal behind the transcript. Long transcripts open at their last 4 MB.
  - **Browser** (⌥⌘3). A web view per session that opens the local server the session prints (like `localhost:3000`). The pick button sends an element's HTML, styles and a screenshot to the prompt.
- **Images and files in the prompt.** ⌘V with an image on the clipboard pastes it as a file path, which Claude Code and Codex read as an attachment. ⌘V with files, or dropping files onto the terminal, pastes their paths.
- **Recent conversations** (⇧⌘O). Switch between Claude Code's recent conversations and the Codex conversation catalog.
- **Usage limits.** The sidebar shows the selected provider's plan limits when available (see [privacy.md](privacy.md)).
- **Updates.** omux checks for new versions about once a day and offers to install them, with the release notes; Help › Check for Updates… checks now. Updates are signed and verified before they're installed.
- **Open folders from anywhere.** Finder's right-click "Open in omux" service, dropping a folder on the Dock icon, or `open -a omux <folder>`.
- **Session links.** `omux://reveal?tab=<id>` brings a session forward, so other apps can take you to it. A session can also be found by its agent: `claude-session=<Claude Code session id>` or `codex-thread=<Codex thread id>`. Programs in a session find their own id in `OMUX_TAB_ID`. A link only selects the session; it never types into or starts one.
- Eighteen themes picked from swatches (Dark, Graphite, Midnight, Dracula, Nord, One Dark, Gruvbox, Solarized, Catppuccin, Tokyo Night, Monokai, Rosé Pine, Everforest, GitHub Light and more), an accent colour for the app, terminal font and size, and the transcript's own font, size, width, density and message style. A quick switcher (⌘K).
